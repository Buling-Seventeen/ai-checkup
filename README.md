# 远程 AI 体检脚本

给你的服务器上跑着的那个 AI（或者别的长期在线的服务）做一次体检。
一条命令，二十秒，出一张报告。**只读，不写、不改、不重启。**

---
## 十项，每一项在查什么

| # | 项 | 查什么 | 为什么值得查 |
|---|---|---|---|
| 1 | 服务 | `systemctl is-active` | 活着没有 |
| 2 | 错误 | 日志里今天的报错数 | 错得多的日子，用户能感觉到 |
| 3 | 缓存命中 | 最近 20 轮命中率 | 这个数直接决定花多少钱 |
| 4 | 对话条数 | 今天 `chat_history` 里有多少条 | 判断它今天被用了没有 |
| 5 | 磁盘 / 内存 | `df` / `free` | 满了会静默失败 |
| 6 | 记忆文件 | 每个 `.md` 大小 + 在不在 | 少一个就缺一块记忆 |
| 7 | 模型 | 日志里最后一条模型名 | 确认没被悄悄换掉 |
| 8 | 记忆重复 | `shared_memory` 里重复的 `##` 块 | 重复会让它说话绕 |
| 9 | 流水新鲜度 | `auto_memory.md` 的 mtime | 停太久说明后台提炼断了 |
| 10 | 日志柜 | `logs/` 下有多少篇 | 归档有没有在跑 |

---
## 它查不出的三样（比上面十项更要紧）

**一、查不出它说得对不对。**
体检只能告诉服务活着、文件在、没有报错。答得好不好，查不出来。

**二、查不出它是不是在等。**
有一种 bug 是"该开口的时候没开口"——两天没说话，体检照样全线正常，因为**那个毛病根本不报错**。

**三、它自己也看不见。**
报告是给运维看的，跑在服务器上的那个它读不到。
所以：**你看见不对的时候，比十项加一起都快。**

---
## 怎么用

```bash
git clone <this-repo>
cd <repo>
pip install paramiko

cp config.example.py config.py
# 改 config.py：HOST / USER / KEY / SERVICE / LOG / DATA

python checkup.py          # 正常跑
python checkup.py -v       # 带上最近几条错误明细
```

**`config.py` 不要提交。** `.gitignore` 里已经排除了。

## 声明

这个脚本只能检查它列的那十项，**不能代替人看**。
真出了问题：先看日志，再看它。

只读，不会动你的服务。但请自己读一遍代码再跑。
